# LearnFlow Authentication Performance Instrumentation

## Scope

This change adds temporary, structured timing logs only. It does not remove or replace Redis, PostgreSQL, Socket.IO, the BFF, Argon2, rate limiting, sessions, cookies, or any existing security architecture.

No authentication business logic, database query, Redis command, Argon2 parameter, or frontend authentication decision was changed.

## Structured log format

Backend logs use the request/correlation ID supplied by the frontend or generated by the API:

```text
[AUTH_PERF] request=<id> stage=<stage> durationMs=<number>
[AUTH_PERF_SUMMARY] request=<id> totalBackendMs=<number> ...
```

Logs never include passwords, password hashes, session tokens, cookies, email addresses, user IDs, IP addresses, or request bodies.

## Instrumented timings

### Backend

The API records:

- Total backend login request duration, including the general rate limiter and response completion.
- General Redis rate-limiter `EVALSHA` duration.
- Login Redis `INCR` duration.
- Login Redis `EXPIRE` duration when the key is first created.
- PostgreSQL user lookup duration.
- Argon2 password verification duration.
- PostgreSQL organization membership lookup duration.
- PostgreSQL session creation duration.
- Audit-log insertion duration.
- Successful-login Redis cleanup `DEL` duration.
- Response generation duration covering session-cookie setup and JSON response creation.

The summary contains:

```text
totalBackendMs
redisLimiterMs
redisLoginMs
dbUserLookupMs
argon2Ms
membershipMs
sessionMs
auditLogMs
redisCleanupMs
responseGenerationMs
```

### BFF

The Next.js login route records:

- Backend fetch duration from the Vercel BFF.
- Total BFF login route duration, including response-body reading and cookie forwarding.

The BFF forwards the same correlation ID to the backend.

### Frontend

The browser records:

- Sign-in submit start through login response completion.
- `/auth/me` request duration.
- Time from successful login response until the dashboard shell has authenticated user state rendered.

These are console timings only and do not alter redirects, caching, retries, or authentication state.

## Files changed

- `apps/api/src/utils/authPerf.ts`
  - Added the temporary timing context, high-resolution timer helpers, stage logger, and aggregate summary logger.
- `apps/api/src/server.ts`
  - Creates the login request context/correlation ID and logs total backend duration when the response finishes.
- `apps/api/src/middleware/rateLimit.ts`
  - Times the general login-request Redis `EVALSHA`.
- `apps/api/src/controllers/authController.ts`
  - Times response generation and passes the request timing context into the existing login service.
- `apps/api/src/services/authService.ts`
  - Times login Redis commands, user lookup, Argon2 verification, membership lookup, session creation, audit logging, and successful-login Redis cleanup.
- `apps/web/src/app/api/v1/auth/login/route.ts`
  - Times the BFF backend fetch and complete BFF route.
- `apps/web/src/components/auth/AuthSwitch.tsx`
  - Times frontend login submit-to-response and stores only a local timestamp for post-login measurement.
- `apps/web/src/features/auth/useCurrentUser.ts`
  - Times `/auth/me` resolution.
- `apps/web/src/components/layout/DashboardShell.tsx`
  - Times successful-login response through authenticated dashboard-shell rendering.
- `AUTH_PERFORMANCE_INSTRUMENTATION_REPORT.md`
  - This implementation report.

## Interpretation

This instrumentation is measurement-only. It does not claim that the login bottleneck is fixed. Production logs from a successful login are required to compare Redis, PostgreSQL, Argon2, session, audit, BFF, and post-login timings.

## Removal

The instrumentation can be removed later by deleting the `authPerf.ts` helper and the timing-only code at the listed boundaries. No functional authentication code should need to be redesigned.
